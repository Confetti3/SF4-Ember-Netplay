# Rematch recovery and connection checks

The reported follow-up symptoms were changing rematch buttons/status text, a dropped match connection that never returned to a usable room, and an unavailable connection check. The normal game log did not contain this play session; these repairs are grounded in reproduced production state-machine failures, not a claim to have replayed that exact match.

The helper required a published fighter selection before authorizing a probe. The player UI publishes that selection on Ready, after offering Check connection. A failing Rust regression reproduced this ordering. Probes now require authenticated room membership, occupied opponent seats, and the exact table revision, without requiring a character selection. The real helper/GGPO integration scenario checks both seated players before sending selections.

The application combined remote connection health with local checkpoint delivery. An ordinary revision could therefore announce recovery and clear pending Ready. SessionController now keeps those observations separate: unfinished application still blocks mutations, while a healthy connection remains healthy. The application observes the completed tick once, so it does not reset the recovery clock with an intermediate healthy observation.

Local abort completion previously required healthy remote control. Its failing regression left the UI Playing and prevented room replacement after the opponent disappeared. Local native/helper retirement now moves a coordinated session to PostMatch while preserving Lost control and blocking Ready. The application runs local cleanup even during a control outage and closes the room on a terminal helper teardown timeout. Native socket retirement and helper closure remain required before resource reuse.

`session-<pid>.log` under the settings directory's `logs` folder records lifecycle changes independently of the optional game logger. Each file is capped at 2 MiB and contains state codes and errors, with no invitations, player names, or endpoint addresses.

Validation commands: `scripts/build-current.ps1`, the `SessionControllerTest` regression, the Rust `probe_binding_requires_committed_fighter_pair_and_exact_revision` test, and `IrohAuthorizedMatchTest` with the freshly built helper. The designated build receipt and `build/current/rematch-followup-*.log` files retain the final validation outcomes. Local helper/GGPO runs do not establish native SF4 or two-PC poor-connection gameplay acceptance.

## Datagram checks and transport hardening (September 13)

GGPO still sends raw UDP to its per-match loopback helper. The helper carries those packets as unordered, unreliable Iroh QUIC datagrams, using direct paths when available and relay fallback when needed. Room coordination uses separate reliable streams. No public Services credential is required for this forwarding, and developer Services secrets are not packaged.

Inbound gameplay classification now runs outside the actor, with one deadline covering the marker and capability proof. This keeps Status, room control and shutdown responsive while an eligible peer supplies incomplete data. Ending a match cancels its pending admission immediately; connection identity prevents a late completion from clearing a newer retry. Existing-member control reauthentication can outlive invitation expiry only while the authenticated endpoint, room and non-retired incarnation remain admitted in both current native and coordination membership. Expiry still applies to new admission.

Check connection measures 100 datagrams at 20 Hz. The optional 30-second benchmark measures 600 datagrams of 1090 bytes (1064 bytes of maximum GGPO payload plus the 26-byte bridge header). Reliable setup and completion messages do not retransmit samples. Results retain actual sends, unique replies, missed replies, p50/p95/p99 RTT, adjacent RTT variation and send-buffer pressure. A route change invalidates a recommendation while preserving a healthy reusable connection. A later check by the other fighter invalidates the superseded recommendation. Neither action changes a fighter's selected delay automatically.

Periodic bridge statistics update the native route and route-change counter. Unexpected termination preserves a typed packet-limit, datagram-limit, send, peer-close or local-socket reason before closure. Diagnostics exports use categorical routes and numeric counters; they do not expose endpoint addresses or invitations.

For a reproducible current-build CLI run, use `scripts/benchmark-current-network.ps1 -Frames 1800 -ConnectionCheck`; add `-RelayOnly` to exercise relay policy. Each fresh output directory retains artifact hashes, synthetic GGPO counters/checksums and the 30-second connection-check lifecycle log. `scripts/test-current-network.ps1 -Cases game,authorized,recovery,four-tables,spectators -Routes default,relay` covers bridge failure/retry, rematches, recovery, four simultaneous tables and a table with fourteen spectators. The benchmark is network/synthetic GGPO evidence, not a native SF4 FPS or international gameplay result. Public relay policy and invitation encoding are unchanged by this work.

Recovery validation also exposed a host-departure race: the retiring helper could keep polling the first remaining voter after a different voter won the election. Successor confirmation now queries all remaining admitted voters concurrently, retaining the existing term, revision and linearizable-quorum proof checks and outer deadline. A stalled follower cannot hide a valid elected successor. The departure fixture also waits for the existing one-second chat cooldown before checking that its post-transfer command is accepted.

The fourteen-spectator acceptance run exposed a GGPO dependency limit: its 16-entry static poll buffer reserved one entry and asserted on the sixteenth registration (UDP plus opponent plus fourteen spectators). The GGPO port now sizes loop registrations to the existing 64-entry poll bound and returns a failure exit code on assertion. A native capacity test registers the advertised player/spectator limits and verifies explicit overflow rejection. Network acceptance also requires each fixture's final completion marker; exit code zero alone no longer counts as completion.

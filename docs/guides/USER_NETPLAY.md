# SF4 Ember Netplay: player guide

Own and install Ultra Street Fighter IV on Steam. Use the complete package on both machines and install the latest Microsoft Visual C++ x86 runtime from https://aka.ms/vc14/vc_redist.x86.exe. An older runtime crashes the game at startup, so the launcher will not start with one; it tells you and offers the download. Under Wine or Proton, Wine's own runtime is accepted.

1. Extract the complete Ember package into a **new writable folder**. Keep the downloaded ZIP and its `.sha256` file outside that folder. Optionally, double-click `preflight.cmd` to check that every file was extracted completely and unchanged. It changes nothing and is not the updater. It ignores other files you keep in the folder but fails on any stray program file, such as a DLL left from an older version. Keep your old launcher installation separate; upgrading from the legacy launcher is a fresh install. Existing Ember preferences remain under `%APPDATA%\sf4e`.
2. Run `Launcher.exe`. Successful startup goes directly to the game. If the game cannot be found, choose the folder containing `SSFIV.exe` in launch recovery; Ember remembers it for later launches. If Ember is already running, a second start says so instead of opening another copy. On first launch Ember may show Recommended game settings: set Frame Rate to FIXED in the game's Options, because other modes break rollback.
3. At the main menu, Ember opens across the game viewport. Set your player name in Settings > Player & controller. There (or with **Choose gameplay controller** on Home), select **Change controller**, release held buttons, press a button on your controller, then release it. Confirm the displayed gameplay device. **Use keyboard** is an explicit alternative; it asks first, because your controller then stops moving through Ember's menus until you assign it again.
4. The host selects **Online play > Create room**, sets the room name, capacity and default rules, then chooses **Copy invitation**. Send that private invitation through your own messaging app. A guest chooses **Online play > Join room**, selects **Paste invitation**, then **Join room**. While the room opens, the row reads **Stop creating** or **Stop joining**. If it has not opened after about 30 seconds, Ember says so; check your connection, or stop and try again. A room that is still opening is not in recovery and offers no Replace room.
5. A joined member starts idle. Select a table's card to open its seat chooser: **Play as P1** or **Play as P2** for an open seat, **Join queue** to wait for one, or **Watch** to reserve a spectator place (**Watch next game** in Table options). Once watching, **Lock in to watch** in Table options makes the next start wait up to 10 seconds for you if you are still leaving the last game; without it the fighters do not wait and you join the game after. A room has up to 16 members and four independent tables.
6. Open **Fighter select** on Home to save your fighter, edition, costume, color and Ultra. You can do this before joining a room or while waiting alone; in a room, an Xbox pad's X opens **Change fighter**. P1 chooses the match stage. When P1 picks **Random**, **Random stage pool** under the stage cards lists every stage; Select skips a stage or puts it back, and Random only picks from the stages left in. The pool is P1's own saved setting and at least one stage always stays in. Return to your table and press A on your own card for **Ready up**; it uses your saved selection. Choose **Unready / unlock fighter** (A again) before changing it. B on your own card leaves your seat or queue place at once, asking first only if that would end a set score or hand the seat to a queued player; a running game blocks it and says why, and during a start held for a locked-in spectator B cancels the start instead.
7. The menu hides for loading and gameplay. A compact, quiet, opaque two-row panel at bottom center shows both fighter names, **Ping**, **Rollback**, and **Delay** without covering the action or SF4's meter areas. Ping is the current gameplay round-trip time in milliseconds; unavailable or stale measurements show a dash. Rollback is the largest replay burst during the preceding second and returns to zero when none occur. Delay is the frame delay both fighters use for this match: the higher of the two Ready choices. Spectators see **Spectating** instead of local delay and do not see fighter ping. In Settings > Interface, choose Small, Standard, or Large Match HUD size and Normal or Raised bottom spacing. The sample preview helps compare sizes; Match HUD On/Off remains available.
8. After a game, both fighters ready again to play the next one. With no set length the same two fighters keep playing until one of them leaves, and the score counts their wins against each other. A host can give a table a set length of first to 1 through 10 (best of 1 to best of 19) and choose who rotates out when a set ends: winner stays (king of the hill), loser stays, or both rotate. Players who rotate out go to the back of the queue, and only members who joined the queue are seated. When a fighter leaves, the next member in the queue takes that seat.

Queued members watch each game while retaining their queue position; leaving the queue ends that watching when the current game does, unless you choose **Watch next game**. Spectators have no Ready action; while waiting outside a match, they can save a fighter choice for their next turn. **Stop watching** leaves the spectator roster while the fighters continue. A table can include up to 14 spectators in addition to its two fighters.

**Connection advice:** Battle setup's **Input delay** row shows Auto or the delay you chose, with the recommended delay and the match delay in its detail. **Check connection** is optional and measures datagram round trips for five seconds after setup. Results show Direct or Relayed, RTT percentiles, RTT variation, actual packets sent, replies and missed replies. Relayed means the match goes through a relay server; it still works, and [troubleshooting](TROUBLESHOOTING.md) explains what can make it direct. If this PC cannot send the scheduled workload, the result reports local overload instead of counting unsent packets as network loss. **Checking connection...** shows that a check is running; wait for it to finish before retrying. If it cannot produce a recommendation, choose **Retry connection check** or set a delay manually and Ready. A new profile is on **Auto**: the connection check runs by itself once both seats are filled, once for each opponent, and Ready waits for it to end, for about twelve seconds at most; a check that fails is tried once more. You ready with its recommendation held between one and three frames, or with two frames if it produced none. Left and Right choose a delay of your own instead, from one to ten, with Auto one step below one; zero is not offered, and a measured or saved zero becomes one. Select on a chosen delay copies the measured value. Ready locks your own delay for that game, and Unready unlocks it. Both fighters play at the higher of their two Ready delays; Input delay's detail shows that match delay once both seats are filled, and "At least" your own value until your opponent readies. Insufficient samples never block manual Ready. Half of round-trip latency is only an estimate, and the recommendation includes a two-frame prediction allowance. A later route change never alters delay during a fight.

**Invitations:** new copied invitations start with `sf4e3:`; Discord uses `emd2:` secrets within its 128-character limit. Use the same package on both PCs. Invitations identify the room's current authority. A copied invitation stays valid for about a week while the room is open, and stops working when the room closes. Copy a fresh invitation after an authority change; stale references cannot admit new members. Already admitted members can reconnect while their current membership remains valid.

**Discord:** keep the Discord desktop app open. Ember shares basic activity, elapsed session time, and room occupancy. A host or guest can invite friends using Discord's interface while the room is unlocked and has space. Accepting an invite starts Ember when needed and waits for the main menu, networking, and your gameplay device. You enter idle and choose a table, queue, or spectator place yourself. If you are already in another room or playing offline, return to the main menu and choose **Switch to invited room**, or **Cancel invitation**. No fight is interrupted.

Settings > Discord includes **Show activity** and **Allow invitations**, both initially enabled. Turning off activity also stops advertising invites. These controls do not revoke invitations already shared or change the host's admission policy. Discord receives no room names, player names, fighter selections, stages, scores, or connection metrics. Discord being closed or unavailable does not prevent normal play.

The room host is separate from the P1 seat. The host can rename the room, lock admission, change capacity, edit rules for a waiting table, and kick members. A kicked peer cannot rejoin that room under another name. The host can cancel an unresolved game after conflicting or missing native result reports; cancellation awards no win and preserves earlier scores. A result counts only when both fighter reports agree. Either fighter can choose **Abandon unresolved game**, and a host who is not playing at that table can **Cancel stuck game** when a finished game never reported its result. That row is available once a game has run for ten minutes without a result; until then it says the game is in progress.

**Host transfer:** the current host can select another member and choose Transfer host. The confirmation starts on Cancel. Normal host departure transfers moderation to the oldest eligible remaining member. Moderation ownership is separate from the technical coordination leader.

**Room recovery:** room actions pause immediately when control becomes unavailable, while a healthy active game keeps its existing gameplay connection. Confirmed results wait for reconciliation, and result deadlines pause during recovery. After 15 seconds, Replace room offers a fresh room with new invitations. It remains unavailable while local gameplay owns its sockets. For incomplete preparation, explicit selection cancels setup and waits for its local connections to close before creating the room. Preferences and local records remain. Recovery continues in the background while you decide. A two-member room cannot recover its old quorum after one member is unexpectedly lost. Larger rooms need their existing voter majority. Replacement never recreates authority for the old room.

**Leaving a room:** choose **Leave room** from the room board or your table, then confirm. **Leaving room...** stays visible until the connection closes, and Ember returns to Home. Hiding Ember keeps you in the room. During **Updating room**, wait for the controls to return; Leave remains available.

**Offline:** select Play Offline. Native Options contains button mappings and graphics settings. Fighter Select saves the choice used by online matches, including rematches, and shows only options available in your game under the current rules.

**Replays:** every Ember match is recorded, and the game keeps the last 30 in Replay Channel > Local battle log (the stock game keeps 10). The launcher also copies each one to `%APPDATA%\sf4e\replays`, so nothing is lost when the game replaces an old one. **Replays** on Home lists those copies with the date, both players and their fighters. Select one and choose **Watch now**: it goes back into the game's list as the newest entry, dated today, with the date it was played as its title, and the battle log opens on it. **Add to game** only puts it in the list. **Open the game's battle log** jumps to that list. Both need the native main menu with no room open, since the battle log is a game screen. Player names show for matches played with this version onward; older copies show fighters only. A row says **Watched** once you have put that replay into the game, and **Spectated** when your PC only watched that match (the game records those too, so a wait in the queue adds other people's matches).

**Training controls:** in offline training, press **F6** to open or close Training Lab. Use the keyboard and mouse: arrows navigate, Enter selects, and Escape returns or closes the panel. **F5** toggles the frame-meter HUD. Controller Start opens the native pause menu when Training Lab is closed. Gameplay inputs are captured while Training Lab is open and until held buttons are released. Record and Play return to practice after acceptance; an error stays visible. Overwriting or clearing a recording requires confirmation, initially focused on Cancel.

**Navigation:** F10 toggles at safe menu states; controller Start opens. Escape / controller Back closes a popup first, then returns from a secondary page. On your own table card in a room, a pad's Back leaves your seat or queue place instead (see step 6); elsewhere on the board it goes to Home. On the keyboard Escape always goes back, and Delete leaves your seat or queue place. Back from Home hides Ember without leaving the room, and Home's Online play row returns to it. In a room, an Xbox pad's X, Y and View, or F, T and C on the keyboard, open Change fighter, Table options and Chat, and pressing the same button again returns to the board (in Chat the keyboard types letters, so Escape or B returns). Change fighter opens on the fighters; picking one goes straight on to its Ultra, and picking the Ultra returns to the room. On the fighter select page, Left and Right on Ultra Combo change it without opening the page. Space also selects and Backspace also goes back, except while you type in a text box. The button prompts follow whatever you pressed last, pad or keyboard. Moving the mouse pointer moves the highlight; clicking selects. Hiding the menu never leaves a room. Reopening is disabled during fights.

**Settings:** Player & Controller (display name and gameplay device), Gameplay Defaults (input delay or Auto, and new-room defaults), Interface (Match HUD, HUD size, bottom spacing, challenger call, interface size and language) and Discord. Leave the room to change these; the gameplay device is the exception, and you can change it while unready, including inside a room. Any controller supported by SF4 can be assigned, including DirectInput sticks and leverless devices. The device stays selected across matches in this game session. Reconnect a disconnected device or explicitly choose another before Ready. Menu navigation is paused during capture; use Cancel or F10 to leave it. Display options remain in the native game menus.

**Challenger call:** when the other fighter at your table readies while you have not, the game's own announcer says "Here comes a new challenger!". Settings > Interface turns it on or off, sets its volume as a share of the game's voice volume (so the in-game voice slider still applies), and **Test challenger call** plays it once at the chosen volume. It calls out once per ready, and again only after a few seconds if the opponent takes the ready back and gives it again.

**Help & about:** controls, version, attribution, a redacted diagnostics export (which includes connection state), the Ember Discord and update checking.

**Updating:** in Help & about, choose **Check for updates**. When one is found, leave your room and choose **Exit and open updater**. The game closes, the Updates window opens with **Download and install** highlighted, and Ember restarts once it is installed. With the game closed, double-clicking `Updater.exe` opens the same window. Installation waits for shutdown and verifies the downloaded ZIP. Your own files are preserved, and the backup from the latest update is kept in `.ember-update-backups`. If an update was interrupted, the launcher restores the previous files the next time you start it, then opens normally. An update that can never be restored is reported once and set aside, and later starts go to the game.

**If the game crashes:** the launcher says so and the files to send are in `%APPDATA%\sf4e\logs`: `sf4e.log`, `sf4e-crash.log` and the newest `sf4e-crash-*.dmp` (the launcher keeps the last five). A heap corruption crash writes a larger `sf4e-crash-*-heap.dmp` of several hundred MB, and the launcher keeps the last two of those. Crash dumps are copies of the game's memory and can hold your current room invitation, player names and chat, so send them privately (a direct message to a developer), never in a public channel. A few crashes stop the game before any of its own handlers run. To catch those too, run this once in an **Administrator** PowerShell; Windows then keeps a full dump in `%LOCALAPPDATA%\CrashDumps`, and `launcher.log` names the file after a crash:

```powershell
New-Item -Path 'HKLM:\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps\SSFIV.exe' -Force | New-ItemProperty -Name DumpType -Value 2 -PropertyType DWord -Force
```

That dump holds the whole game's memory (about 500 MB), so zip it before sending it.

This experimental release has automated transport coverage. Actual SF4 host/join, native fights, repeated rematches, spectators, different-network and clean-machine results must be recorded separately. The source repository contains the implementation record at `docs/design/EMBER_IMPLEMENTATION.md`; this package guide has no repository-relative links so it remains valid as `START_HERE.md`.

# SF4 Ember Netplay — troubleshooting

- **Launcher says the Visual C++ runtime is out of date:** Ember will not start with an older runtime because the game would crash. Choose Yes to open the Microsoft download, install the x86 Redistributable, then start Ember again. Under Wine or Proton, Wine's own runtime is accepted.
- **Ember is already running:** a second start shows this message instead of opening another copy. If you cannot see Ember, end Launcher.exe and SSFIV.exe in Task Manager, then start it again.
- **Preflight reports an unexpected program file:** a DLL or EXE that is not part of this package is in the folder, usually left by extracting over an older version. Extract the package into a new empty folder. Other files you keep there, such as the downloaded .sha256, are only reported and ignored.
- **Game not found:** choose the directory containing SSFIV.exe in recovery, then Retry launch. Ember remembers that folder and uses it on later launches. Steam must be installed and the game owned.
- **Missing networking helper:** extract the complete package, including sf4-net.exe. Offline remains available. Restart Launcher after restoring files.
- **Launch or injection failed:** close recovery, run preflight.cmd and review `%APPDATA%\sf4e\logs\launcher.log`. Retry through recovery. No unrelated processes are terminated.
- **Character art missing:** portraits come from the installed game. For most fighters the packaged original outfit stands in when the game's picture cannot be read. Most alternate colors have no preview picture; those show "Preview not available" by design. A picture that fails to load is retried, then logged once as `Selection art ... unavailable` (or `... uses a fallback`) with the file and error. In game this goes to `%APPDATA%\sf4e\logs\sf4e.log`; on the launcher's recovery screen it goes to `launcher.log` in the same folder. Include that line in a report.
- **Display problems:** use the native game Options menu. Ember does not override fullscreen or window behavior.
- **Invalid invitation:** paste the entire private invitation. Old broker room codes and direct-IP addresses are no longer supported.
- **Room rejected:** use the same release as the host, a distinct player name, and a room that is unlocked and has free capacity. Choose **Stop creating** or **Stop joining** (or **Leave room** once inside), fix the cause, then try **Create Room** or **Join Room** again.
- **Room still opening after 30 seconds:** Ember says the room has not finished opening. Check your connection, or choose **Stop creating** or **Stop joining** and try again.
- **Connection lost:** check the status line on the room screen, or use Help & About > Export diagnostics to save the connection state. Leave and rejoin with a current invitation. A continuing fight may have unavailable control-plane verification; its health should not be inferred from the HUD alone.
- **Check connection says Relayed:** your two networks could not connect directly, so match traffic goes through a relay server. Matches still work; use the recommended delay, which already accounts for the extra distance. A direct connection usually needs only one of the two players on a friendlier network: turn on UPnP (sometimes called automatic port forwarding) in the router, turn off any VPN, or play from a home connection instead of a mobile hotspot, school or work network. Matches and room control prefer UDP port 45760 (45761 to 45763 for extra copies on the same PC; Help & About > Export diagnostics shows the one in use). Forwarding UDP 45760 to your PC in the router and allowing `sf4-net.exe` in Windows Firewall usually gives other players a direct path for the match even when both networks are strict; a forwarded port does nothing while the firewall blocks it. Some internet providers share one public address between many customers; those players cannot forward a port and often stay relayed.
- **Ready pending:** wait for the other player and preparation acknowledgement. Selections remain locked while readiness is pending. Leave is explicit.
- **Preferences could not be saved:** keep the window open, resolve a read-only or busy settings directory, then choose **Retry saving**. Original settings and migration backups remain under `%APPDATA%\sf4e`.
- **Update failed:** retry from Help & About or `Launcher.exe --updates`. Installation requires orderly game shutdown. Logs are in `%TEMP%\sf4-netplay-update.log`; previous product files are preserved in `.ember-update-backups`. Do not delete those recovery copies while investigating. If an update was interrupted, the launcher restores it on the next start. One that cannot be restored is reported once and its record is kept as `.ember-update-transaction-v1.json.failed` in the install folder; include it in a report.

Before reporting a problem, follow [Saving logs for a bug report](SAVING_LOGS.md) to save the full logs folder and export diagnostics from Help & About. For online match issues, collect logs from both players. The diagnostic export intentionally omits invitations, capabilities, player names, credentials, arbitrary log text and settings backups. Never paste a private invitation into a public issue.

Old VPS, Qt and direct-IP instructions are under `docs/archive` and do not describe this build.

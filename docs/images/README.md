# Ember interface captures

The home, room, King of the hill, fighter and costume PNGs are captured directly from the production Ember UI using `UiRenderTest`
with the `--readme-shots` option. The room names, members, chat and profile are fictional sample data. The game is not launched by this renderer.
Portraits are decoded from an owned Steam installation; selection artwork comes
from the repository's credited assets. See [attribution](../../ATTRIBUTION.md).

Generate after building the current source:

```powershell
pwsh -NoProfile -File ./scripts/capture-readme.ps1 -GameRoot 'C:/Games/Steam/steamapps/common/Super Street Fighter IV - Arcade Edition'
```

The script renders every screen once, in English at 1280 x 720, converts the
pictures it needs and removes the renders.

Home, room, fighter and costume selection retain the full 1280 x 720 viewport.
Only BMP-to-PNG conversion is applied; UI text, geometry and artwork are not
composited or retouched.

The normal UI regression suite retains its long-name and long-chat stress cases;
the README option substitutes readable sample names and chat for presentation.

## Guide pictures

The step pictures under `guides/` are captured by the same run, from the same
English 1280 x 720 renders, and written as WebP with libwebp's `cwebp -q 85`
(`cwebp` must be on `PATH`). `manifest.tsv` lists which render each one is,
`captured.txt` the commit the last capture ran on, and `scripts/wiki/stale.py`
fails the wiki build when the interface changed after that commit.

The pictures the manifest marks `uilab` come from the same run through
`UiLab.exe` (src/ui/lab), the shell in a window with made-up data: the training
pages, the room board with a guest, the match HUD and replay strip over the
menu art, the post-match prompt and the updater, each at 1280 x 720.

The pictures it marks `game` are screenshots of Ember 1.4.0-nightly20261018
running in the game on a Steam Deck: the frame meter, frame data and dummy
recording over a fight, the game's own Graphics settings and the stage previews.
Each is cropped to the game's 1280 x 720 picture and written with the same
`cwebp -q 85`. Retake them by hand when those screens change.

## In-game frame meter

`ember-frame-meter.png` is an in-game training screenshot supplied by the project
owner. The original PNG is retained unchanged. It shows Juri versus Hakan with
Ember's player timelines and frame-advantage readout. This image is separate from
the renderer captures above and is not generated by `capture-readme.ps1`.
Game imagery remains covered by the [artwork attribution](../../ATTRIBUTION.md).

## Steam Deck install

`steamdeck-1-download.png` to `steamdeck-5-library.png` are Desktop Mode
screenshots from a Steam Deck (SteamOS 3.8) running the real install, taken by
`scripts/steamdeck/capture-guide.sh` over SSH:

```bash
scripts/steamdeck/capture-guide.sh deck@steamdeck
```

A browser click and the Continue button of KDE's warning cannot be pressed over
SSH. After capturing those two screens the script downloads the file itself and
marks it trusted the way Continue does, so screens 4 and 5 follow the same
install a player starts by hand. `steamdeck-6-game-mode.png` was taken on the
same Deck in Game Mode with `gamescopectl screenshot`. None are retouched. The
tile's artwork in `assets/steamdeck` comes from `scripts/steamdeck/build-steam-art.py`.
